# Visual Iterate

**目标**：用可观察的负反馈改进同一作品，不把多次随机生成或“更高级一点”当成迭代。本 Skill 负责评价与控制循环，制图可复用 `visual-explain`、`visual-story`、`visual-art-direction` 或宿主工具。

## 执行契约

开始前从用户输入提取并锁定：**Intent**（受众与要传达的一句话）、**Artifact**（媒介/尺寸/语言）、**Invariants**（不得改变的内容和关系）、**Evidence**（事实来源与待验证项）、**Budget**（轮数/停止条件）。信息已足够就直接做。

- 区分 **N 版图**（V1 至 VN，N−1 次修改）与 **迭代 N 次**（V1 基线 + N 次修改，至 V(N+1)）；不擅自把后者当成 N 版。
- 对指定旧图的编辑或前后比较，必须能实际访问旧图；不能凭描述冒充同源编辑。
- 用户只要求评价就停在评价；只要求单次修改不自动启动多轮。

## 每轮必走的闭环

1. **看图、先过正确性门槛。** 实际查看当前成图及其目标阅读尺寸，核对文字、事实、数字、箭头、关系、遗漏、截断。语义错误优先于审美；不能看图时不声称已检验。
2. **八维三级 Critique。** 按 [量表](references/critique-rubric.md) 对 Function、Audience、Hierarchy、Composition、Visual Contrast、Additional Contrasts、Meaning、Narrative/Sequence **逐项记录** `Strong / Fair / Weak`（不适用须说明 N/A）。每项附一条**该图可观察的证据和判断理由**；受众效果仅是待验证推断，不能冒充实验结果。不得用随意的总分代替量表。
3. **提取可执行负反馈。** 从证据中选 **1–3 个最影响 Intent 的问题**，逐项写 `维度 → 可观察缺陷 → 对目标的影响 → 明确修改动作`；注明本轮不变的元素。禁用只有“更美、更高级、更简洁”的空泛反馈。
4. **定向修改并实际出图。** 能编辑旧图就以旧图为目标；否则显式注明重生成。优先保留已验证部分。文字/数据/表格精度要求高时使用可控布局或确定性工具；不要靠缩小字号塞满一页。
5. **对比复评。** 实际查看新版，与旧版按**相同八维定义**比较，记录 `Improved / Regressed / Unchanged / Unproven` 及视觉证据；新增事实错误、语义回退或不可读须先修复，不得继续累积版本。变化微小就承认未改进，不能因版本号或生成时声明而自动升级评级。

**循环约束**：每轮的下一次修改必须来自该轮真实 Critique；不得预先编造所有轮的批语。最后一版**同样必须完成八维评估和回归检查**。如下一轮缺少可执行证据、达到目标或收益很低，可停并说明；用户指定精确轮数时尽量执行，无法完成则如实报告实际轮数。

## 最小留痕与交付

多轮任务每版至少保留：
`Vn + 实际成图引用 | 正确性门槛 | 八维评级及各自证据 | 关键负反馈与修改动作 | 相对上一版的改善/回退/未变/未证实 | 下一步`。
可用 [简化日志](references/iteration-log.md)；完整量表放日志，不强塞进画面。每轮记录不得事后伪称实时评价。

交付用户要求的**真实成图**及简短结果；用户要回顾过程时提供逐版评价和反馈。禁止虚构展示中的评分、质量曲线、用户测试结果或下载路径；示意数据应明确标注。最终总结准确区分“生成版本数”和“完成的修改轮数”。

**特殊情况**：作品若在解释 Critique Framework，同时分别评价**整张教学图**和**图中的示例作品**，不能混用两层的得分或证据。
