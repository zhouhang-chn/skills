# Visual Iterate — Critique-driven Visual Iteration

## 核心目标

用可解释、可追溯的评价驱动连续作图，而不是重复“生成一张更漂亮的”。每轮回答：**作品要完成什么任务？具体哪里做到了/没做到？依据是什么？改哪里？结果是否真的改善？**

本 Skill 是**迭代与评价层**，不是新的绘图引擎。根据主任务复用 `visual-explain`（解释/结构/教学图）、`visual-story`（系列视觉叙事）、`visual-art-direction`（风格/插画），或宿主支持的其他制作能力；缺少这些 Skill 时仍可独立执行下述流程。

## 何时使用

- 对新图或已有图片开展多轮“生成 → 评价 → 修改 → 复评”。
- 用户要求按明确评价框架打分、找到问题并改进，或要求记录学习/迭代轨迹。
- 在多版本间比较设计质量、查找回退与过拟合，并决定是否继续迭代。

单纯“一次画图”不自动启用完整多轮循环；用户只要求评价时只评价，不擅自生成。用户只要改图时要交付实际新图，而非用文字代替。

## 输入：先形成一条简短的设计契约

从对话中提取并锁定，信息充分就直接执行，不要求填表：

1. **Intent**：这张图要让谁理解/感受/完成什么；一句话核心主张。
2. **Artifact**：画面类型、交付媒介、语言、长宽比、真实阅读尺寸。
3. **Content invariants**：不能改的事实、名称、数字、关系、已确认设计决策与用户明确禁止项。
4. **Evidence boundary**：来自用户资料、已核实来源、视觉直接观察，还是仅为假设；缺口不可伪造。
5. **Iteration scope**：本轮要修复的缺陷、允许更改的元素、预算和停止条件。未指定时逐轮处理最重要的 1–3 项；不要无限自动生成。

涉及指定旧图的编辑或真实前后对比，必须取得可访问的目标原图。无法读取图像时不能凭历史文字重画后冒充同一作品的对照。

## 主循环

### 0. 建立基线

从已有成图开始；没有成图且用户要求制作时生成 V1。记录目标、来源与冻结内容。为可检验的陈述建立独立依据：图上可见的属性可直接观察，目标受众效果等需要外部验证。

### 1. 实际查看成图，做 Critique

参考 [八维三级量表](references/critique-rubric.md)，按以下顺序检查：

- **正确性先行**：事实、文字、数字、箭头、关系、遗漏、引用是否准确？结构/语义有错先修正，不以视觉美感抵消错误。
- **八维评价**：Function、Audience、Hierarchy、Composition、Visual Contrast、Additional Contrasts、Meaning、Narrative / Sequence。每项给 Strong / Fair / Weak，并写一条具体可观察的证据与评价理由；确不适用时明确说明原因，不硬套低分。
- **阅读情境**：在目标尺寸下检查字号、拥挤、裁切、视线顺序、含义和视觉噪声，不能只看放大的图。
- **证据分层**：`Observation（看得见）` / `Interpretation（设计判断）` / `Outcome（用户效果，需验证）`。不要把假设当成实测结论。

`Strong / Fair / Weak` 是定性判断，**不是客观数值、也不是必须让八项全部变 Strong 的优化目标**。有依据地保留 Fair，比没有证据地给 Strong 更好。

### 2. 诊断并选取下一轮修改

按 `目标受损程度 × 证据可信度 × 修改可行性` 选最重要的 1–3 个问题。每个问题写成：

`Criterion → Observation → Reasoning → Intervention → Expected effect`

先修目的/事实/含义，再修信息层级/构图，再修视觉对比/细节；此优先级可按具体任务调整。优先删无关装饰与重复解释，而不是不断加文字和元素。

### 3. 定向修改与渲染

- 只修改有依据的问题，保留已通过且用户认可的部分；局部反馈不无故全局重设计。
- 关系/含义错误需要重组时允许大改；只想调风格时冻结语义与关键信息。
- 对密集文字、精确表格、公式、数据图表优先使用可确定控制字体和布局的工具；视觉生成工具适合插画、构图探索和可容忍少量文案的图。必要时分成两张图或将完整量表放到伴随文档，**不要缩小字号装入一页**。
- 如宿主有图像编辑能力，优先使用可访问旧图定向修改。必须重生成时尽量保留相同信息、尺度与比较基准；标明不是逐像素同源编辑。
- 遵守宿主的图像生成、编辑、文件交付和回复规则。不能用 prompt、空路径或假造文件代替成图。

### 4. 复评与比较

检查实际新图后，沿用相同评价定义，与旧版并列复评；记录：

- **Improved**：哪项改善、可见证据是什么。
- **Regressed**：是否引入小字、信息过载、语义错位、装饰无关、事实错误或此前修过的问题复发。
- **Unproven**：哪些仅能声称“更符合视觉标准”，还不能声称任务完成率/用户理解/转化率上升。
- **Unchanged**：什么保持不变；不要为了演示进步而改分。

特别警惕生成者与评价者是同一 AI 时的**自我确认偏差**。如果新版八项全 Strong，或每项都无差别变好，主动寻找反例并重新检查；不要自动反向扣分。

### 5. 结束或继续

默认每轮交付**本轮实际成图 + 极简评估/剩余问题**；用户只要图时按宿主规则只交付图。必要时追加 [迭代记录模板](references/iteration-log.md)，但不自动输出长报告。

达到用户目标且无关键缺陷、下一轮收益边际很低、工具/证据限制已明确、或用户指定上限时停止。仅在用户要求持续迭代时，才继续多轮；默认建议少量轮次后交给用户选择，不为凑版本数强行修改。

## 特别约束：评审框架图的双层评价

当作品本身是一张解释 Critique Framework 的信息图时，必须区分：

1. **外层**：对整张教学信息图的八维评价（它是否教得清楚）。
2. **内层**：图中被用作例子的海报/界面的八维评价（例子的分数是否准确）。

两层证据不能混用。内层的 Before/After 分数不因外层“设计更好看”就自动上调；图中显示的分数要能从案例证据追溯，并与文字描述一致。

## 验收自检

- 用户要解决的问题和目标受众是否清晰？图像是否服务 Intent 而非装饰？
- 画面上的文字、名称、数值、关系和来源是否正确？有无文字乱码？
- 重要内容是否按合理顺序被看见，真实显示尺寸是否可读？
- 每个评价是否有支持它的观察，而不是套话/臆测？
- 新版是否解决上一版的问题，是否重新引入旧问题？
- Before/After 是否对比同一任务，是否把审美评级冒充实际用户效果？
- 交付是否包含用户请求的真实图片及可用文件？无法看到像素时不宣称已做视觉验收。
